# Focus release: defaults, deprecations and the removal path (2026-10)

LeanCTX is the **Context Gateway for AI Systems — Select · Control · Prove**.
This release removes what serves none of the three, measured first
(`ee/delivery/FOCUS_ANALYSIS_2026-10-15.md`). Every changed default can be set
back unless the table says it was retired. The 36 retired MCP tools (34, plus
`ctx_task` and `ctx_intent` on 2026-10-17) are removed; calling one returns the successor
or the way forward instead of "Unknown tool" (§3). The remaining removals
below name the files and callers to cut.

## 1. Changed defaults (this release)

| Setting | Was | Now | Why (measured) | Restore |
|---|---|---|---|---|
| `cognitive_mode` | `full` | retired (the key is ignored; the migration removes it) | `auto` reads picked the chunked `cognitive` mode: +33 % `ctx_read` tokens, +25 % per session; on the retrieval A/B corpus `full` gave +74 % read output with identical R@5 and MRR; learned co-access made output depend on earlier sessions (#498) | — (`ctx_read mode="cognitive"` and `"mdl"` render the map view) |
| `autonomy.cognition_loop_enabled` | `true` | `false` | the background loop rewrote stored knowledge (synthesis, decay, compaction) with no recorded decision | `[autonomy] cognition_loop_enabled = true` (a project file may switch it on only in a trusted workspace) |
| `minimal_overhead` with a config.toml that does not name it | `false` (a field-level `#[serde(default)]` used bool's default) | `true`, the documented default | every user with a config file ran the non-minimal path: larger MCP instructions and post-read enrichment on every `ctx_read` | `minimal_overhead = false` |
| built-in profile `coder`: `autonomy.auto_prefetch` | `true` | unset (off) | after every `ctx_read`: a graph walk plus up to ten admitted file reads under the session-cache lock, result seen only by an internal event — **~1.1 s per read** | — (retired with the read-path drivers on 2026-10-17; `ctx_prefetch` stays as an explicit tool) |

## 2. Fixed in this release (Control and performance)

- **The read path no longer loads the code graph per call.** Post-read
  enrichment opened — and on a cold project synchronously built — the graph
  under the session-cache lock, also when no enabled feature used the result
  (the related-files hint is off in every built-in profile); the session-start
  hook and the pre-read mode gate re-parsed the whole JSON index on every call
  until the property graph was built. All three now use only a populated
  property graph and otherwise schedule the background build. Together with
  the two defaults in §1 (`coder` prefetch, `minimal_overhead`), measured with
  the release build on a 2,500-file repository (fresh session, same workload,
  Linux): `ctx_read` p50 **1,263 ms → 158 ms** on first read and
  **~1,210 ms → ~100 ms** on re-reads; with `minimal_overhead = false` the
  read path stays fast (131 ms, development build).
- **`ctx_compose` no longer refuses unchanged results** with "source authority
  changed or could not be verified" (~3 % of calls): a timed-out ranking worker
  invalidated its caller's policy view after the view had ended. The refusal
  now names the reason when it is genuine.
- **`ctx_compose` ranking reuses the resident search index** instead of
  deserializing it from disk on every call. The associative section uses only
  a built graph and, with `cognitive_mode = off`, only the static graph. In a
  cold session ranked sections can still differ while the index builds
  (3 of 18 eval queries in the release measurement).
- **Path jail:** read-only access to the host's own session output —
  `~/.claude/projects/<slug>/<session>/{tool-results,subagents}`,
  `~/.cursor/projects/<id>/{agent-tools,terminals}` — to the host's private
  scratch dir `<tmp>/claude-<uid>/` (only when owned by the user and not
  writable by others), and to `~/.pyenv/versions`. Credentials beside them
  (`~/.claude/.credentials.json`, `~/.cursor/projects/<id>/mcp-auth.json`) and
  other conversations' transcripts stay jailed.
- **Gateway refusals name the setting behind them** (`max_inspected_bytes`,
  `detector_timeout_ms`, `classification`, `secrets/injection = "block"`, an
  unloadable `config.toml`).
- **Passwords in URLs are redacted** for every common scheme
  (`https://user:pw@host`, `ssh://`, `amqp://`, …), not only database URLs.
- **`ctx_work_graph`** errors say what to do next (register the agent; which
  transitions are allowed).
- The `[cognitive: high echo ratio]` suffix is gone: it compared the task text
  with tool *output* and told the model to "generate novel content".

## 5. Binary size: grammar policy (decided 2026-10-15)

Tree-sitter parse tables are 54 % of the binary's symbol bytes; LeanCTX's own
code is 21 %. OCaml, Julia and Haskell — the three largest, used only for
signature extraction — are separate Cargo features (`grammar-ocaml`,
`grammar-julia`, `grammar-haskell`, bundled as `grammars-long-tail`) and are
**no longer part of `default`** (owner decision 2). Without them `.ml/.mli/.hs/.jl`
fall back to the regex signature extractors; these languages were never
graph-indexed, so search and graph results do not change. Build with
`--features grammars-long-tail` to keep the parsers. Measured on Linux x86-64,
release profile, stripped: with the grammars **109.9 MB**, default now
**95.3 MB (−14.6 MB, −13 %)**.

## 8. Work Graph: the host starts agents (after 3.11.5)

LeanCTX no longer launches agents. `ctx_work_graph action="execute"` (Codex CLI
only; telemetry: one installation tried it, without success) is removed and
answers with the way forward:

| Before | Now |
|---|---|
| `execute` with `connector`, `model`, `max_attempts` | the host launches the child; `action="start"` binds it to the node and returns `launch.env` (the child's delivery profile) and `launch.unset_env` |
| process supervision, cancellation signals, one retry | the host owns the process; `cancel`, a receipt or an expired lease stops the node and revokes the child's delivery at once |
| usage parsed from CLI output (`execution_receipt_ref`) | `receipt` with the `execution_fence`; figures are reported (`usage_source: "reported"`) and stay inside the node and chain budgets |
| `lean-ctx pair <CODE>` (never implemented) | removed; the command prints this pointer |

Fixed with it: a child taken with `action="claim"` carries a fence, and its
receipt used to require a measured receipt nothing produced, so it could not
finish. `receipt` and `cancel` now also accept the owner of the delegating
parent node. Details: [docs/architecture/work-graph-host-start.md](../architecture/work-graph-host-start.md).
