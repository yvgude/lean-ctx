# Local observations and evidence boundaries

LeanCTX can expose local Runtime observations such as context volume, tool
output, cache behavior, and configured cost calculations. These views help an
operator inspect a declared local workflow; they are not a public analytics
platform or a universal performance claim.

## What a local observation can say

A local report can describe the data it observed under the active configuration,
including the scope, inputs, model-price assumption, and calculation method
where those facts are available. It should be treated as a diagnostic, not as
a claim about every agent, repository, model, or customer workload.

## What it cannot say on its own

- A displayed percentage is not proof that another workload will achieve the
  same result.
- A calculated dollar value is not a provider invoice or a business outcome.
- A local counter does not prove preserved task quality.
- An implementation dashboard or report command does not create a hosted
  analytics, team, or enterprise offering.

## Proof discipline

A gain is valid only for a comparable baseline and treatment, a declared
quality threshold, visible methodology, and inspectable evidence. A cheaper
failed task is not a win.

Local Receipts and offline-verification primitives are **Available** as
implementation substrate. The common benchmark, quality, comparison, and
evidence flow is **Research**; a universal verified-savings claim is not
available. See [Proof & audit](16-signed-savings-ledger.md) and the canonical
Product Architecture (`docs/internal/vision/PRODUCT-ARCHITECTURE.md`, internal — not in this repository).
