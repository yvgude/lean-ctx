# Historical / Research — unified distribution

> **Superseded planning record.** This document is not an accepted product
> direction and does not authorize a public registry, marketplace, commerce
> rail, managed addon distribution, or package-management service.

## Current boundary

LeanCTX is the local Context SDK for existing agents. Its available scope is
local Runtime context control and local evidence foundations. Signed .ctxpkg
substrate exists locally; Context Kits are **Research** work.

A package, addon, manifest, signing module, billing-related code path, or
registry reference in the repository does not create a public customer-facing
distribution product.

## Historical proposal

Earlier planning explored putting knowledge, skills, extensions, and grammars
behind one package format and distribution service. That proposal is retained
only to explain historical implementation vocabulary and possible future design
constraints.

It is not current guidance for authors, operators, customers, or sales. In
particular, do not describe LeanCTX as a Context OS, package manager,
marketplace, hosted catalog, or billing platform.

## Conditions before reconsideration

Any distribution capability would need an explicit product decision, bounded
public contract, local-first fallback, security and provenance guarantees,
compatibility and revocation policy, support ownership, and evidence that it
does not move marketplace, cloud, or agent-building concerns into the current
OSS product.

Until then, use the internal Product Architecture (`docs/internal/vision/PRODUCT-ARCHITECTURE.md`, internal — not in this repository)
as the only product authority.
